SECTION 1

Why This Series Starts Here

Every LangChain tutorial starts with from langchain_openai import ChatOpenAI — and that's fine for getting something working. But it hides something important: every LLM call is ultimately an HTTP POST to an API endpoint. Knowing that endpoint — its request structure, its response format, its error codes — is the difference between a developer who can only follow tutorials and one who can debug, optimise, and extend them.

This series teaches the agentic stack from the inside out. We start at the raw API layer, then add LangChain's abstractions in Module 02, agents in Module 04, and multi-agent graphs in Module 06. By the time you're building production systems in Tier 4, every component will make sense because you built it from scratch first.

CONCEPT

An LLM API is a stateless HTTP endpoint. Every call is independent — no memory, no continuity. When LangChain adds "memory", it's reconstructing conversation history in the prompt on every call. When an agent "reasons over multiple steps", it's making multiple separate API calls. Understanding this makes the entire agentic stack easier to reason about.

SECTION 2

The OpenAI and Anthropic APIs

Two APIs dominate the current LLM landscape for builders: OpenAI's Chat Completions API and Anthropic's Messages API. They have slightly different request structures and philosophies, but the same fundamental model: you send a list of messages, you get a completion back.

OpenAI: Chat Completions API

The OpenAI Python SDK (openai==1.x) wraps the POST /v1/chat/completions endpoint. The message list has three roles: system (instructions), user (input), and assistant (prior model responses, for multi-turn conversations).

python · openai_basic.py
import os
from openai import OpenAI

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))  # never hardcode keys

response = client.chat.completions.create(
    model="gpt-4o-mini",             # check platform.openai.com for latest
    messages=[
        {"role": "system",  "content": "You are a concise technical assistant."},
        {"role": "user",    "content": "What is a transformer model in one sentence?"},
    ],
    temperature=0.3,               # lower = more deterministic
    max_tokens=150,
)

# Response structure
text    = response.choices[0].message.content
p_tok   = response.usage.prompt_tokens
c_tok   = response.usage.completion_tokens
total   = response.usage.total_tokens

print(text)
print(f"Tokens — prompt: {p_tok}, completion: {c_tok}, total: {total}")
CODE NOTE — TEMPERATURE

temperature=0.3 is a reasonable default for extraction and classification work. Values near 0 make the model near-deterministic; values above 1.0 make it erratic. It is not a quality dial.
